# Управление локальными изменениями репозитория (Патчи)

Этот скил регламентирует работу агента при обнаружении существующих изменений в рабочей копии (грязный репозиторий, uncommitted / untracked files).
Вместо надежды на пассивный текст в инструкциях, скил предписывает вызов **конкретного исполняемого скрипта** `scripts/manage-patch.mjs`.

---

## 1. Проверка состояния перед началом работы

Перед взятием задачи в работу или переключением веток выполни проверку:

```bash
node scripts/manage-patch.mjs check --json
```

Если репозиторий чист (`clean: true`), сразу переходи к выполнению задачи.

---

## 2. Что делать, если скрипт `scripts/manage-patch.mjs` отсутствует в репозитории

Если файла `scripts/manage-patch.mjs` нет в проекте:
1. **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО падать с ошибкой или прерывать работу.**
2. **Предложи пользователю решение:**
   - Сообщи: *"В репозитории есть локальные изменения, но скрипт `scripts/manage-patch.mjs` не найден. Предлагаю создать скрипт в проекте для надёжного сохранения и последующего восстановления патча, либо сохранить патч напрямую через Git."*
   - При согласии пользователя скопируй/создай `scripts/manage-patch.mjs` из шаблона этого скила (`.agents/skills/manage-repo-patch/scripts/manage-patch.mjs`) в `scripts/manage-patch.mjs` проекта.
   - Если пользователь предпочитает команду Git без создания скрипта, выполни:
     ```bash
     git add -N .
     git diff HEAD > patch_pre_task.patch
     git reset
     git checkout -- .
     git clean -fd -e patch_pre_task.patch
     ```

---

## 3. Сохранение изменений перед выполнением задачи

Если скрипт присутствует и обнаружены изменения:

1. Вызови команду сохранения:
   ```bash
   node scripts/manage-patch.mjs save [имя_патча] --json
   ```
2. Скрипт:
   - Сохранит полный unified diff (включая untracked файлы) в `patches/patch_<timestamp>.patch`.
   - Запишет метаданные в `.json` и обновит `patches/latest.json`.
   - Очистит рабочее дерево, сделав репозиторий чистым и готовым к работе.
3. Сообщи пользователю путь к созданному файлу патча и зафиксируй его в комментарии к задаче (`tracker_add_comment`).

---

## 4. Выполнение задачи

Выполни задачу в чистом репозитории по согласованному плану:
- Реализация изменений;
- Запуск тестов и сборки;
- Создание коммита по регламенту проекта.

---

## 5. Восстановление изменений после завершения работы

После того как задача реализована и закоммичена, восстанови сохранённый патч:

```bash
node scripts/manage-patch.mjs restore
```

### Обработка результата:
- **Успех (код возврата 0):** Патч успешно наложен. Сообщи пользователю: *"Локальные изменения успешно восстановлены в рабочую копию."*
- **Конфликты (код возврата 1):**
  - **Файл патча гарантированно сохранён на диске и не удалён.**
  - Сообщи пользователю:
    ```
    ⚠️ При автоматическом наложении патча возникли конфликты.
    Файл патча сохранён: <путь к патчу>
    Вы можете применить оставшиеся части вручную: git apply --reject <путь к патчу>
    ```
  - Процесс сдачи задачи не блокируется, пользователь может разрешить конфликты в удобное время.
