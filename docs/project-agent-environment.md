# Окружение агента в worktree

В «Команда агентов» можно один раз настроить агентов и выбрать «Сохранить как базовую».
После подтверждения новые проекты наследуют профили и инструкции, подключения моделей,
этапы и маршруты, навыки и MCP с назначениями ролям. В ранее настроенном проекте
выберите «Вернуть базовую команду» и сохраните настройки проекта, чтобы включить наследование.
Путь к репозиторию, команды запуска приложения и проверок, ветка и бюджеты задаются в проекте.

Обычное сохранение в проекте позволяет переопределить, например, только текст инструкции.
Обновление модели в базе дойдёт и до такого проекта. В карточке агента можно вернуть
базовую инструкцию, а вверху раздела — всю базовую команду. Возврат применяется при
сохранении проекта. При несовместимом обновлении (например, локальный агент ссылается
на удалённое подключение) панель показывает конфликт и последнюю рабочую конфигурацию.
Уже созданные запуски используют свой снимок настроек.

В разделе «Команда агентов → Навыки и MCP» доступна общая библиотека трекера. Поиск работает
по названию и условию применения. В «Каталоги и импорт» доступны коллекции Superpowers,
Anthropic, Vercel, Nx, NestJS и Angular. При выборе коллекции браузер получает список файлов
через GitHub API. Если исчерпан лимит запросов, список загружается через jsDelivr.
Сам текст навыка браузер читает с raw.githubusercontent.com. Другие коллекции можно найти на [skills.sh](https://skills.sh/).
Создайте навык или импортируйте текст инструкции по
публичной HTTPS-ссылке. Для репозитория GitHub можно выбрать файл SKILL.md из списка.
Найдите файлы в левой колонке и перенесите нужные в «К импорту». Кнопка «Прочитать»
открывает инструкцию для чтения. Кнопка «Открыть следующий на импорт» открывает редактор первого файла из списка.
Перед сохранением доступны текст, источник и редактирование. Прямой URL должен разрешать
чтение из браузера (CORS). Импорт копирует один Markdown-файл до 128 000 символов. Скрипты, шаблоны и
дополнительные документы должны находиться в окружении проекта, если инструкция их требует.
Отметьте нужные навыки. В разделе «Команда агентов» выберите навыки и MCP в карточке роли,
затем сохраните настройки проекта. Эти назначения общие для профилей одной роли в проекте.

При постановке задачи в очередь сервер фиксирует версии. На старте этапа модель получает
названия и краткие условия применения назначенных ей навыков. API-агент читает полный
текст инструментом `read_skill` порциями по запросу, а CLI-агент открывает указанный файл в рабочей копии.
Правки библиотеки доступны новым запускам. Обязательные правила репозитория,
перечисленные ниже, по-прежнему загружаются целиком.

Worker перед вызовом модели загружает существующие корневые AGENTS.md,
AGENT_INSTRUCTIONS.md и CLAUDE.md. Он передаёт их текст в инструкции роли:
повторно читать неизменившиеся файлы агенту не требуется.
Для обязательных дополнительных документов, выбранных скилов и MCP создайте
в репозитории docs/agent-environment.json и закоммитьте его до запуска:

```json
{
  "version": 1,
  "instructions": [
    { "path": "docs/ARCHITECTURE.md" }
  ],
  "skills": [
    { "path": "docs/skills/testing/SKILL.md", "roles": ["developer", "tester"] }
  ],
  "mcp": [
    {
      "name": "project-search",
      "command": "node",
      "args": ["{worktreeRoot}/tools/project-search.mjs", "--root", "{worktreeRoot}"],
      "envVars": ["PROJECT_SEARCH_TOKEN"],
      "tools": ["search_symbols"],
      "roles": ["developer", "reviewer"]
    }
  ]
}
```

Это пример: пути и имена инструментов должны существовать именно в вашем проекте.
Все три списка необязательны. Без roles запись применяется ко всем ролям.
Пути документов относительны корню checkout, выход через .. или symlink/junction
запрещён. Пропавший обязательный файл останавливает запуск до модели.
Общий лимит загружаемого текста — 48000 символов; превышение требует выбрать
меньше скилов, автоматического усечения нет. Ссылки из SKILL.md не раскрываются
рекурсивно; обязательные дополнительные документы перечисляйте явно.
Вложенные AGENTS.md автоматически не собираются: агент читает применимые
локальные инструкции при работе с соответствующим каталогом.

Подключения MCP можно добавить в разделе «Навыки и MCP» или описать в манифесте.
Кнопка «Добавить MCP» открывает ручную форму и шаблоны для Playwright, Context7 и GitHub.
«Поиск по реестру MCP» ищет по имени в [официальном реестре](https://registry.modelcontextprotocol.io/).
Для совместимого HTTPS-адреса Streamable HTTP нажмите «Выбрать сервер». Подключённый
воркер запросит список инструментов. Отметьте нужные или нажмите «Добавить без инструментов»,
чтобы выбрать их позже. После сохранения настроек такое подключение хранится в проекте.
Назначить его роли можно после выбора инструментов. Имена переменных
для авторизации задаются на воркере. Для пакетных серверов и других способов авторизации
откройте документацию издателя и заполните поддерживаемый транспорт вручную.
Выбор шаблона заполняет черновик. Для Playwright на воркере нужны npx и браузер.
Если первый запуск упирается в тайм-аут загрузки npm, подготовьте пакет на воркере командой
`npx -y @playwright/mcp@0.0.86 --version` и повторите получение инструментов.
Имена в настройках и манифесте должны быть уникальны. Для stdio задайте команду и массив
аргументов, для Streamable HTTP — URL и при необходимости имя переменной воркера
с bearer-токеном. HTTP без TLS поддерживается для localhost. Для stdio воркер запускает
команду из каталога проекта. Для HTTP список доступен и до выбора каталога. Отметьте разрешённые инструменты
или введите их имена вручную. Назначения ролям применяются после сохранения настроек.

Управляемые подключения поддерживаются для Codex CLI, Antigravity CLI, OpenCode,
DeepSeek Harness и Model API. Worker делает
initialize и listTools с ограничением времени 15 секунд на сервер, проверяет
все перечисленные tools и закрывает пробное соединение. Прикладные инструменты
на проверке не вызываются. Отказ транспорта, отсутствие переменной или инструмента
останавливают запуск до вызова модели. Необходимость проектного MCP у другого
runner также вызывает явную ошибку до модели.
Codex затем открывает своё соединение с тем же транспортом и списком разрешённых
инструментов. Antigravity, OpenCode и DeepSeek Harness получают временную конфигурацию
для локального MCP-моста. Мост показывает и вызывает только инструменты, назначенные
роли. Для OpenCode 2 worker запускает отдельный локальный сервер и ждёт подключения
MCP до первого запроса к модели. Для DeepSeek
Harness требуется CLI с поддержкой `--patch` и пакетом `@deepseek-ai/dsh-mcp-client`.
Назначенные библиотечные скилы доступны всем CLI через файлы в `.sat/skills/<role>/`
и каталог скилов в инструкциях этапа.
Проверка доступности не гарантирует, что конкретный вызов инструмента успешен.

{worktreeRoot} подставляется в command и args. Worker и MCP запускаются
с cwd рабочего checkout. Не задавайте там абсолютный путь к основному
репозиторию. Профиль — доверенный исполняемый конфиг: он запускает команды
с правами worker. Указывайте имена переменных окружения, секреты в JSON не храните.
Серверы codegraph и simple-ai-tracker зарезервированы существующим конвейером.
Произвольные MCP из настроек аккаунта Codex по-прежнему отключаются.
Неперечисленные skills аккаунта не считаются обязательными скилами проекта.

В журнале видны Project policy loaded (путь, короткий SHA256, размер),
MCP preflight (проверенные имена инструментов), Environment preflight OK.
Полная квитанция без тел файлов и значений секретов находится в
.sat/environment-<role>.json внутри checkout.
Это подтверждает загрузку worker и доступность MCP. Фактический вызов
Codex отображается отдельной строкой MCP <server>/<tool>: вызов/завершён.
Прочитанный скил не доказывает соблюдение требований: это проверяют тесты и ревью.

После правок обязательные проверки и squash-слияние выполняет действующий
worktree-конвейер. Автоматическое завершение реализации означает review:
done выставляет пользователь. Прямой режим в основном checkout отложен в SAT-28.
