# Окружение агента в worktree

Worker перед вызовом модели загружает существующие корневые AGENTS.md,
AGENT_INSTRUCTIONS.md и CLAUDE.md. Он передаёт их текст в инструкции роли:
повторно читать неизменившиеся файлы агенту не требуется.
Для обязательных дополнительных документов, выбранных скилов и MCP создайте
в репозитории docs/agent-environment.json и закоммитьте его до запуска:

```json
{
  "version": 1,
  "instructions": [
    { "path": "docs/ARCHITECTURE.md" }
  ],
  "skills": [
    { "path": "docs/skills/testing/SKILL.md", "roles": ["developer", "tester"] }
  ],
  "mcp": [
    {
      "name": "project-search",
      "command": "node",
      "args": ["{worktreeRoot}/tools/project-search.mjs", "--root", "{worktreeRoot}"],
      "envVars": ["PROJECT_SEARCH_TOKEN"],
      "tools": ["search_symbols"],
      "roles": ["developer", "reviewer"]
    }
  ]
}
```

Это пример: пути и имена инструментов должны существовать именно в вашем проекте.
Все три списка необязательны. Без roles запись применяется ко всем ролям.
Пути документов относительны корню checkout, выход через .. или symlink/junction
запрещён. Пропавший обязательный файл останавливает запуск до модели.
Общий лимит загружаемого текста — 48000 символов; превышение требует выбрать
меньше скилов, автоматического усечения нет. Ссылки из SKILL.md не раскрываются
рекурсивно; обязательные дополнительные документы перечисляйте явно.
Вложенные AGENTS.md автоматически не собираются: агент читает применимые
локальные инструкции при работе с соответствующим каталогом.

Проектный MCP сейчас управляется только для Codex и stdio. Worker делает
initialize и listTools с ограничением времени 15 секунд на сервер, проверяет
все перечисленные tools и закрывает пробное соединение. Прикладные инструменты
на проверке не вызываются. Отказ транспорта, отсутствие переменной или инструмента
останавливают запуск до вызова модели. Необходимость проектного MCP у другого
runner также вызывает явную ошибку до модели.
Codex затем открывает своё соединение с тем же транспортом и allowlist.
Проверка доступности не гарантирует, что конкретный вызов инструмента успешен.

{worktreeRoot} подставляется в command и args. Worker и MCP запускаются
с cwd рабочего checkout. Не задавайте там абсолютный путь к основному
репозиторию. Профиль — доверенный исполняемый конфиг: он запускает команды
с правами worker. Указывайте имена переменных окружения, секреты в JSON не храните.
Серверы codegraph и simple-ai-tracker зарезервированы существующим конвейером.
Произвольные MCP из настроек аккаунта Codex по-прежнему отключаются.
Неперечисленные skills аккаунта не считаются обязательными скилами проекта.

В журнале видны Project policy loaded (путь, короткий SHA256, размер),
MCP preflight (проверенные имена инструментов), Environment preflight OK.
Полная квитанция без тел файлов и значений секретов находится в
.sat/environment-<role>.json внутри checkout.
Это подтверждает загрузку worker и доступность MCP. Фактический вызов
Codex отображается отдельной строкой MCP <server>/<tool>: вызов/завершён.
Прочитанный скил не доказывает соблюдение требований: это проверяют тесты и ревью.

После правок обязательные проверки и squash-слияние выполняет действующий
worktree-конвейер. Автоматическое завершение реализации означает review:
done выставляет пользователь. Прямой режим в основном checkout отложен в SAT-28.
