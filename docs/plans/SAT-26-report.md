# SAT-26 — компактный прогресс, patches и CodeGraph

Последний SAT-10 остановлен по cumulative input limit 500000. Три завершённых попытки: analyst 126448, повторный analyst 296930, developer 633617 input; суммарно 1056995, включая 901376 cached input, разница 155619. Это не размер одного контекстного окна. Наблюдаемое окно журнала содержало 561366 символов CLI progress, в том числе выводы команд на десятки тысяч символов. Размер сохранённого JSON не доказывает, что весь этот JSON повторно отправлялся модели: исходный tool output входит в её работу, журнал — отдельная копия. В дальнейшем диагностические заметки нельзя добавлять в description через clarification: это меняет ключ требований и заставляет повторять анализ. Ранее такие уточнения изменили SAT-10 перед повторным аналитиком; в этой работе SAT-10 description и лимиты не менялись.

Native stdout разбирается локально для outcome/usage. В progress идут только разрешённые короткие события: результат команды, изменённые пути, завершение ответа и релевантная ошибка/trace. Source, aggregated_output, patch/diff, MCP arguments/results и agent_message не передаются в tracker. Worker setup/checks также используют компактный вывод. Исторические JSON-события в читаемой консоли не разворачивают исходники. Старый исходный журнал доступен только при явном открытии/скачивании; исторические данные не удалялись.

Codex tool_output_token_limit уменьшен до 800. Handoff требует узкий поиск, CodeGraph одного метода с maxFiles=1, чтение нужного диапазона и apply_patch. Model API имеет explore_code, диапазоны read_file до 40 строк и edit_file с единственным точным совпадением; write_file создаёт только новые файлы. Результаты tool не печатаются в progress. Исходники не минифицируются ради числа строк; outcome/планы не теряются ради UI.

Реальный worker готовит приватный .codegraph каждого worktree через init/sync до вызова модели, runtime игнорируется Git. Codex MCP ограничен единственным codegraph_explore и явно привязан к worktree; другие MCP остаются выключенными. Windows npm-обёртка CodeGraph инициализировала MCP, но последующий запрос через SDK зависал. Проверен прямой комплектный runtime с --path/--no-watch: соединение и запрос Sample.value успешны, вернули 518 символов из нужного тестового проекта. CLI init/explore и текущий CodeGraph MCP также проверены без модели. Worker синхронизирует граф перед каждой ролью; общий индекс основного репозитория не используется. CLI-провайдеры имеют CodeGraph CLI fallback; API-провайдер — explore_code.

Регрессии: source/patch/MCP sentinel отсутствуют в прогрессе при chunked JSON, но outcome/usage сохранены; subprocess success/failure trace; чистый исторический UI; приватные graph init/sync и argv; API ranges/exact patch с буквальным $& и запрет перезаписи существующего файла. Платные модели и SAT-10 не запускались. Сравнительную экономию provider tokens не измеряли.

Проверено: 131 тест, typecheck, server/web build, Docker build; headless verify-run-console (фильтры, Unicode/ANSI, отсутствие source sentinel, copy/download, scroll и размеры окна). Отдельная stdio-сессия CodeGraph через платформенный runtime прошла запрос без модели.

Аудит результата SAT-10: после повторной аналитики создано уже четыре подзадачи. В S1 есть незакоммиченные изменения трёх файлов; focused automation.spec даёт 4 passed/1 failed (сдвиг тестовых часов нарушил ожидание lease timeout). Код SAT-10 не менялся и не сливался. Это подтверждает непригодность текущего большого маршрута для маленькой задачи, а не успешное прохождение пользовательской задачи. Диагностика записана обычным комментарием SAT-10 без изменения description.
