# SAT-20: стабильная модалка и команды задач

Модалка команды имеет фиксированную адаптивную высоту 88dvh и ширину 1100px с ограничением viewport. Прокручиваются панели вкладок; футер остаётся в flex-разметке с непрозрачным dialog background. Смена вкладок не меняет геометрию диалога.

Добавлены две области: настройки проекта и команда выбранной задачи. Для задачи отдельно сохраняются agents/pipeline/executionMode; путь проекта, подключения, setup/checks и лимиты наследуются от пространства. Есть явный сброс к наследованию. Несохранённые черновики команд сохраняются при переключении контекста модалки, общая инфраструктура при загрузке задачи всегда берётся из текущих настроек проекта.

POST запуска теперь не перезаписывает общие настройки. Прямой запуск карточки без черновика использует команду этой задачи, если она сохранена. Снимок уже созданного запуска не меняется от последующей настройки проекта/задачи. MCP task_team позволяет читать/сохранять/reset настройки без обхода правил доступа к задачам.

Явный режим developer требует ровно один этап developer и существующий план. Остальные модели не вызываются. Worker выполняет configured checks после разработки (и при local merge — обычные проверки кандидата). Падение проверок не допускает review; автоматического добавления других ролей нет. Успешный результат проходит testing/review и остаётся на приёмку пользователя, done не выставляется. Стандартный team режим сохраняет прежний порядок developer/tester/reviewer.

Проверки: scoped inheritance/reset/isolation и immutable run snapshots; worker на временном Git repo вызывает ровно одного fixture developer на запуск, проходит проверки до review, а отрицательная проверка оставляет failed. Полный набор 136 passed, typecheck и server/web build passed. Headless проверка геометрии всех вкладок, непрозрачного футера, scope/preset/save/reset и portrait/landscape passed. Общая verify-automation регрессия выбора моделей/инструкций/чернового запуска/закрытия-повторного открытия тоже passed. Пока команда новой задачи загружается, редактирование, save и start блокируются, чтобы не применить настройки предыдущей задачи; повторный targeted UI тест прошёл. Выполнен один визуальный просмотр финальной модалки. Реальные модели и рабочая база в тестах не использовались.

Существующие проектные команды пользователей автоматически не сокращаются: режим и область выбираются явно. Начинать проверку developer-only следует с небольшой задачи с готовым планом; успешный fixture не выдаётся за успешный платный end-to-end прогон.
