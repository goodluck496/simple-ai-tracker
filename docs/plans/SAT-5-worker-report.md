# SAT-5: исправление подготовки и восстановления worker

## Причины подтверждены журналом SAT-2
Run 4bf591ed-b2f3-4852-a46b-a7a2058c2608: setup=[]; npm install агента прерывался, осталась неполная node_modules; первый успешный developer-ответ не дошёл до CompleteStage из-за git add/ignored .sat. Resume не повторял analyst, но повторно запускал developer. Время/токены повторно расходовались на диагностику того же окружения.
Учтённые попытки: 4,478,711 входных токенов (4,294,912 кешированных), 16,291 выходной; это накопленный вход, не уникальный размер контекста.

## Изменения
- WorktreePreparation до модели: runtime .sat исключён через Git info/exclude; npm-проект с lockfile получает управляемый npm ci при первом setup/изменении manifest-lock-runtime/обнаруженной неполной установке. Маркер записывается только после успешной подготовки. Установка в shared symlink/junction node_modules автоматически запрещена.
- Проверка основных runtime entry/exports учитывает пакеты SDK/themes без рабочего корневого импорта; реальный основной checkout проходит inspect, повреждённый SAT-2 checkout обнаруживался как неполный. Это не побайтовая проверка целостности всех файлов пакетов.
- Успешный ответ агента сохраняется атомарно в .sat до staging/commit. Checkpoint связан с run, stage/revision, настройками, содержимым задачи/плана/вопросов и состоянием файлов. При совпадении повторяются служебные операции, а не модель. Изменённые исходники/HEAD останавливают восстановление; изменённый контекст не переиспользует старый ответ.
- Успешные проверки tester кешируются до подтверждения этапа. При failed/interrupted resume сохраняет текущий этап; возврат к developer после вопросов и функциональных замечаний остаётся.

## Проверки
- Детерминированная интеграция: transient git commit failure, затем transient acknowledgement failure tester, два resume. Результат review; developer/tester/reviewer вызваны по одному разу; успешный configured check выполнен один раз; runtime не попал в Git.
- Fixture setup: неудачная установка не создаёт success marker; повторная подготовка восстанавливается; удалённый entry-file обнаруживается и чинится.
- Checkpoint: другой контекст не использует результат; изменение исходника обнаруживается и блокирует автоматическое восстановление.
- npm test: 87 passed / 0 failed; npm run typecheck pass; npm run build server+web pass.
- Дополнительно в старом worktree SAT-2 выполнен npm ci --no-audit --no-fund (913 пакетов, около 2 минут). После него сборка server+web и целевые automation/API тесты прошли. Все 9 staged-файлов SAT-2 сохранены; модель и очередь не запускались.

## Границы
Локальные checkpoints не восстанавливают задним числом ответы прежней версии worker. Старый SAT-2 run не продолжался. При изменившемся checkpoint требуется осмотр, не молчаливая повторная генерация. Процесс host-worker должен быть перезапущен на новом бандле; старый процесс не обновляется при замене файлов. Полный параллелизм/junction/MR и лимиты бюджета остаются в SAT-3.
