# SAT-3 — реальная приёмка 2026-10-27

Пользователь разрешил проверку после перезапуска. Основной MCP доступен, настройки master/local/parallel=2 сохранились; активных пользовательских запусков не было. SAT-1 и другие пользовательские задачи не запускались. Все задачи приёмки — синтетические, в отдельных временных tracker-сторах и Git-репозиториях.

## Результат

- Два отдельных процесса worker одновременно выполняли настоящие Codex/gpt-6-luna роли developer/tester/reviewer. Worktree разные, исходный base SHA одинаковый.
- Независимые изменения полей одной строки создали реальный Git-конфликт. Решатель сохранил оба требования: master содержит `a=1,b=1`. История master — исходный коммит плюс два squash-коммита; исходные ветки сохранены.
- Один процесс принудительно завершён с кодом 73 после Git-публикации, до подтверждения трекеру. После истечения lease и продолжения новый процесс подтвердил готовый коммит без повторного вызова модели и без нового коммита. Для ускорения только часы синтетического tracker были сдвинуты на 120 секунд.
- Первый решатель создал посторонний acceptance.log: защита отклонила результат. Явный повтор только интеграции использовал сохранённый исходный SHA, вызвал одного решателя, не повторял роли и успешно слился. Автоматический неограниченный повтор не включался.
- Две настоящие копии трекера собрали сервер и Angular через один readonly npm-кеш с package junction. Затем изменение lockfile отсоединило первую копию и вызвало отдельную установку; обе копии снова успешно собрали сервер/UI. Запись в общий package.json отклонена, изменяемые кеши независимы.
- После отсоединения всех потребителей общий кеш успешно снят с защиты и удалён штатным pruneUnused. В завершении тестового скрипта обнаружено и исправлено повторное закрытие того же SQLite-координатора; сама очистка уже завершилась успешно.

## Найденные и исправленные дефекты

1. Модель помещала commitMessage в summary. Добавлен обязательный отдельный ключ в JSON Schema для Codex и явный пример в prompt. Валидация русского формата коммита сохранена.
2. Вложенный CLI видел посторонние MCP пользовательского окружения. Теперь worker отключает их только флагами дочернего процесса, сохраняя CodeGraph для индексированного checkout. Обработаны desktop-injected транспорты и уже отключённые виртуальные серверы; глобальный config.toml не меняется.
3. Общая инструкция просила локальный лог без указания папки, конфликтуя с запретом решателю создавать посторонние файлы. Логи направлены в .sat/logs, resolver явно запрещает отчёты вне .sat.
4. Успешное восстановленное слияние сохраняло старое сообщение об истёкшей lease. Финальный summary теперь содержит реальное source -> target/candidate SHA.

## Ограничения и расход

Проверка не гарантирует правильное семантическое разрешение любого конфликта. Отказ сохраняет основную ветку и результаты. Общий readonly-кеш подходит проверенному npm/Angular проекту; произвольные lifecycle scripts и сторонние пакеты могут требовать isolated. Полная холодная подготовка и отдельная npm ci на Windows занимают минуты: изначальный таймаут приёмки 8 минут был недостаточен; проверка продолжена на тех же папках. В тестовом скрипте исправлено создание отсутствующей .cache после отдельной npm ci.

16 реальных модельных вызовов, включая неудачные приёмочные прогоны: input=1,108,069, cached input=777,728, output=5,887. Cached input включён в общий input; это не стоимость и не число уникальных токенов. Ещё два технических прогона завершились до вызова модели из-за настройки desktop-injected MCP, после чего обработка исправлена. Проблему большого расхода нельзя считать полностью решённой: даже успешные роли/решатель всё ещё используют заметный контекст, а native usage поступает с задержкой.

Платные прогоны не повторять автоматически. Для воспроизведения использовать opt-in scripts/smoke-sat3.ts. Состояние реальной карточки после отчёта — review; done выставляет пользователь.
