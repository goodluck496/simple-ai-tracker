# SAT-39: сортировка отдельных колонок

В каждой колонке PrimeNG p-select: ручной порядок, дата создания сначала новые/старые, дата обновления сначала новые/старые. Выбор хранится в localStorage по пространству и статусу; испорченное или недоступное хранилище безопасно возвращает ручной порядок. При запрете записи выбранный режим продолжает работать в текущей сессии.

Даты сортируются до lazy pagination. Группы фич и одиночные карточки в режиме дат объединяются по дате, подзадачи остаются в группе и сортируются тем же способом. Группа определяется датой самой фичи. Сохранённые позиции карточек не меняются. Ручная перестановка внутри колонки отключена при сортировке датами, перенос между статусами доступен. Ручной порядок возвращает прежнее представление.

Проверки: unit regression для всех направлений, стабильного порядка при равных датах, невалидных дат и сохранности позиций; полный suite 164/164 (tsx compact reporter, concurrency=4); typecheck и чистая Docker-сборка server/web. Headless Playwright на временном хранилище: независимость колонок, выбор после reload, сортировка всех 25 карточек до первой страницы, updatedAt, восстановление ручного порядка, namespace другого пространства и fallback при испорченном JSON. Отдельный сценарий SAT-38 проверяет все типы создания и ручную смену типа.

Проверки не используют реальные пользовательские карточки или платные модели. Посторонние UI-правки не включаются в коммит и production image.

Дополнительная финальная headless-регрессия на release image: фича располагается между отдельными задачами по своей дате; два её ребёнка сортируются внутри группы, дубли отсутствуют. Все проверки прошли.
