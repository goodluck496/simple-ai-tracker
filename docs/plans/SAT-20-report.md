# SAT-20: очередь, история и очистка ресурсов

## Поведение

Очередь открывается во весь экран поверх канбана. Рабочая вкладка содержит только queued/running/integrating. Остальные попытки видны в истории (включая архивированные), с поиском и фильтром выбранной задачи. История ограничена последними 200 запусками выбранного пространства/задачи; это явно подписано. Карточки компактные, этап и лимиты выбранного запуска видны над журналом, подробности открываются сбоку. Журнал остаётся в нижней части, карточки и журнал прокручиваются отдельно.

Очистка файлов и удаление истории разделены. После verified merged автоматически создаётся host-запрос очистки; ошибки не откатывают состоявшееся слияние. Очистку можно повторить. Для failed/cancelled/interrupted и иных неслитых запусков требуется отдельное подтверждение удаления неперенесённого кода. Permanent delete удаляет только run/events/archive запись, сохраняет карточку/планы/отчёты/комментарии. Для запусков, которые worker уже забирал, сначала требуется подтверждённая очистка. Продолжение после начала очистки запрещено, включая случай частичного удаления.

## Границы очистки

Docker не удаляет произвольные Windows-пути. Сервер формирует snapshot, host worker повторно вычисляет путь через RunWorkspace, проверяет Git common dir, generated path и branch identity и берёт общий run lease. Проверяются все рабочие копии до первого удаления. Без discard грязные исходники и изменившийся после review SHA сохраняются. Автоматическая очистка требует подтверждённого squash candidate в target branch.

Удаляются зарегистрированные собственные worktrees запуска/детей/integration вместе с private node_modules, .sat, .codegraph и build artifacts. Ссылки/junctions отвязываются без обхода их целей. Исходный репозиторий и его node_modules не затрагиваются. Shared dependency cache сохраняется и не удаляется вместе с junctions. Это одна общая копия зависимостей, а не оставшаяся приватная рабочая копия.

Собственные source branches удаляются при сохранённом source SHA или явном discard. Старые integration branches без достоверного publication SHA сохраняются и перечисляются в результате; они не выдаются за удалённые. Неперенесённый код не очищается только на основании статуса review/done карточки. Очистка idempotent, ошибки/истечение host mailbox видны и допускают повтор.

## Проверки

- Временные Git repos: защита source root, run lease, dirty/unmerged/renamed/changed-after-review branches, shared cache junction target, verified merged cleanup, повторная очистка.
- In-memory tracker: active/history/archive separation, explicit discard, active guard, fenced host acknowledgement, failed/offline cleanup retry, delete/cancel и сохранность карточки.
- Headless UI на временных данных: рабочая очередь/история, отсутствие resume принятой задачи, PrimeNG checkbox подтверждения, cleanup ack, permanent delete и отмена, portrait/landscape; консоль/даты/фильтры/копирование/скачивание/scroll без ошибок страницы.
- Полный набор: 134 passed; focused filesystem/service проверки после уточнения identity/publication прошли. Typecheck, server и web build прошли. Обе headless проверки прошли, в desktop журнале проверяется минимально полезная высота; выполнен один визуальный просмотр.
- Модели не запускались. Deployment и состояние живой очереди фиксируются в карточке SAT-20.

Старые неудачные SAT-10 будут перенесены в архив через MCP без удаления рабочих копий: это не разрешение уничтожить неперенесённый код прошлых попыток. Автоматический pipeline SAT-10 по-прежнему считается неуспешным, ручной приёмочный коммит master сохранён.
