# SAT-5: устойчивый worker без повторной генерации после инфраструктурного сбоя
1. Воспроизвести ignored .sat и зафиксировать текущие причины из SAT-2. Изменения SAT-2 не трогать.
2. Перед моделью проверять npm-зависимости в worktree. Для npm-проекта с lockfile при отсутствии/неполной установке выполнить управляемый npm ci (или настроенный setup), дождаться завершения. Проверять пакеты и основные entry-файлы; ошибку подготовки завершать до агента. Маркер подготовки привязать к manifest/lockfile и проверять окружение повторно.
3. Корректно исключить runtime .sat из Git-операций и сохранить результат успешно завершённого агента до commit/check/CompleteStage. Использовать локальный атомарный checkpoint с проверкой SHA, stage/revision, конфигурации, контекста и состояния файлов. Возобновлять инфраструктурную часть без модели только при совпадении; вопросы/замечания и изменившийся контекст требуют нового этапа.
4. При resume failed/interrupted не возвращать tester/reviewer к developer автоматически; изменения по замечаниям по-прежнему обрабатывает CompleteStage.
5. Регрессии на временных Git/npm fixtures без платных моделей: ignored runtime, подготовка до агента, сбой commit/CompleteStage и восстановление без повторного агента, изменение файлов/контекста инвалидирует checkpoint.
6. Сфокусированные тесты, полный npm test, typecheck, build; отчёт и коммит. Не запускать автоматизацию SAT-2 и не переставлять её в done. Подключение новой версии worker требует перезапуска host-worker после сборки.
