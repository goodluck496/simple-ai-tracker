# SAT-19 — согласование бюджета после аналитики

Причина реального SAT-10: аналитик завершился за один вызов (126448 input, 96640 cached input, 29808 input без чтения кеша, 2356 output). Минимальное разбиение требует 9 общих вызовов при разрешённых 6. Это не исчерпание 500000 input и не падение CLI: сервер ошибочно сообщил VALIDATION_FAILED вместо бюджетной паузы.

Новый запуск сохраняет outcome/checkpoint и предложение аналитика как отчёт, переходит в Waiting с budgetApproval.requiredCalls. Новая версия исполняемого плана и дети пока не создаются. До явного повышения лимита resume запрещён. UI показывает минимум и отсутствие запаса на исправления, подставляет минимум только в редактируемый черновик; сохранение остаётся действием пользователя. Автоматического повышения и модельного вызова нет.

Связи related/duplicates исключены из семантического ключа checkpoint: регистрация диагностической карточки не должна заставлять аналитика повторять работу. Требования, вопросы, родитель/дети и блокирующие зависимости остаются значимыми.

Регрессия временного Git fixture проверяет Waiting, запрет раннего resume, пустой список детей, добавление диагностической связи, повышение бюджета с сохранением usage и восстановление аналитика без дополнительного вызова, затем прежние ревью/сборку фичи. Headless очередь проверяет уведомление, отсутствие кнопки продолжения до согласования и редактируемый минимум. Полные тесты, typecheck, build выполняются перед коммитом.

Историческая ошибка SAT-10 не переписывается автоматически: запуск остаётся остановленным, лимиты не меняются. Для продолжения нужны явное согласование бюджета и действие пользователя. Платных модельных вызовов для исправления не выполнялось.
