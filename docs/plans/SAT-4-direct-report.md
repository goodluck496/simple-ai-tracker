# SAT-4 — консоль выполнения и компактный handoff

## Реализовано
- Shared RunConsoleDecoder: JSONL, переносы между порциями, кумулятивный stdout/stderr без дублей, команды и exit code, сообщения/итоги агента, ошибки (включая вложенные API-ошибки), Unicode и очистка ANSI/OSC. CLI item ID изолированы между этапами. Транспортные обёртки и неизвестные payload не выводятся как обычный текст.
- Angular-консоль: моноширинные строки с временем/ролью/уровнем, фильтры, копирование, scroll-follow только у нижнего края и «К последним строкам». Состояние сбрасывается при смене запуска. Сырой просмотр раскрывается отдельно; дублирующий большой lastMessage над консолью убран.
- Ограниченное окно: 600 строк, до 8000 символов на строку, до 512 KiB незавершённой записи. UI сообщает о сокращении и недостающей части записи. В деталях по-прежнему окно последних 200 сохранённых событий, не бесконечная DOM-история.
- /api/automation/runs/:id/log потоково отдаёт все сохранённые события JSONL порциями по 200, с учётом workspace и backpressure. Новый progress сохраняется порциями по 12000 символов без потери хвоста. Старые уже обрезанные данные восстановить невозможно.
- Worker ProgressBuffer заменяет молчаливое сохранение последних 12000 символов: backlog ограничен 2 MiB, при переполнении отбрасываются целые JSONL-границы с явной меткой потери. Скачивается полная сохранённая история, включая такие метки; это не обещание безлимитного захвата.
- AgentHandoff: полный согласованный план и требования сохраняются; повторные машинные отчёты исключаются, остаются до 3 релевантных комментариев по 1000 символов. Контекст ограничен 40000 символами с отказом до модели при превышении, feedback — 3000, diff-preview — 16000. Полные журналы не подмешиваются в следующий prompt.
- Общие инструкции требуют выполнять план без мета-повествования, выводить одну строку на успешную команду, релевантный error/trace при сбое, краткий JSON-итог. Это инструкции и ограничение handoff, а не общий жёсткий бюджет токенов и не перехват внутренних shell-инструментов стороннего CLI.

## Проверки
Дополнительная регрессия: после слишком большой незавершённой JSONL-записи парсер пропускает её хвост до разделителя, затем восстанавливает обычный вывод. Сырой хвост не попадает в читаемую консоль; итоговый полный прогон остаётся 96/96, сборка проходит.
Сфокусированные тесты парсера/HTTP-stream/handoff PASS. Полный npm test: 96 passed / 0 failed. Typecheck PASS; server+web build PASS. Изолированный verify-run-console.ts PASS: фрагменты JSONL, stdout/stderr/exit code, ANSI/Unicode, безопасный текст, фильтры уровня/этапа, clipboard, полный raw-download, 600 строк, ручной scroll без скачков, переход вниз, смена запуска, отмена и 390/844/1440px, JS/console errors=[]. Повторный verify-queue.ts после замены журнала PASS. Скриншот просмотрен один раз; найденное дублирование lastMessage устранено и проверено программно.
