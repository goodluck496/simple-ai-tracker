# SAT-2: убрать ожидающий запуск из очереди

## Решение
Использовать существующую отмену запуска, сохраняя задачу и журнал. Сделать отдельное понятное действие для queued; не удалять историю запусков.

## Шаги
1. На карточке queued в automation-queue добавить кнопку «Убрать из очереди» вне основной кнопки выбора карточки; то же название в деталях. Running/Waiting сохраняют действие «Остановить».
2. Выполнять серверную отмену с ожидаемым статусом queued. Проверять статус атомарно вместе с записью; при гонке с claim вернуть конфликт и обновить UI, не останавливая уже работающий процесс под видом удаления из очереди. Существующий cancel для остановки running оставить совместимым.
3. На время запроса блокировать повторные действия; после ответа обновлять очередь и карточку, выводить понятную ошибку. Отменённый запуск перемещается в завершённые и остаётся доступен в истории.
4. Добавить регрессии queued cancel → worker не забирает запуск, сохранность задачи/журнала, повторная постановка, гонка с claim и изоляция workspace.
5. Проверить UI на временном сервере, прогнать тесты/typecheck/build, создать отдельный коммит и отчёт; перевести в review.

## Модули
web/src/app/components/automation-queue/automation-queue.component.html и .ts; server/src/automation/automation-service.ts; server/src/api/routes/automation.routes.ts; типы действия/параметров при необходимости; тесты automation/queue.

## Приёмка
Ожидающий запуск можно явно убрать из очереди без удаления карточки и истории; работающий запуск останавливается отдельным действием; отменённый запуск не забирается worker. Миграции БД и перезапуск многоагентного конвейера не требуются.
