# SAT-38

Причина: сигнал формы type первоначально содержал task и не синхронизировался с input createType при первом открытии без существующей карточки. Значение из меню использовалось только при последующем resetAfterCreate.

Исправлено: начальные type/status читаются реактивно из inputs; локальные сигналы выставляются в untracked. Ввод заголовка и ручная смена типа не сбрасывают выбор.

Проверено на чистой production-сборке через Headless Playwright и временное хранилище: меню Создать → Баг/Фича/Задача создаёт соответствующий тип; ручная смена Баг → Задача сохраняется. Ошибок браузера нет. Server/web Docker build и typecheck пройдены. Посторонние изменения пользователя не включены.
