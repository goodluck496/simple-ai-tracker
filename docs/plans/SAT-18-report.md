# SAT-18 — декомпозиция и общая фича

Аналитик возвращает структурированный DAG из 2–12 небольших задач, каждая с полным планом, либо вопросы пользователю. Непустые вопросы имеют приоритет даже над pass: сохраняется предложенный план, но дочерние карточки и разработка не создаются. После ответа аналитик уточняет решение. Ясное разбиение автоматически создаёт карточки, планы, связи зависимостей и последовательность developer/reviewer.

Дочерние этапы входят в исходный запуск: один журнал затрат, лимит вызовов, токенов, времени и исправлений. Минимальное количество оставшихся вызовов проверяется до создания детей. При недостатке конвейер останавливается с объяснением. Пользователь может явно увеличить лимиты остановленного запуска в очереди и продолжить; потраченный бюджет и checkpoint сохраняются, агентам MCP-инструмент повышения лимитов не выдан.

Каждый ребёнок имеет собственную ветку `sat-child/<run>-<key>` и worktree. После ревью существующий SquashIntegration публикует один commit в частную ветку фичи `sat/<run>`, используя durable receipt. Следующие дети получают уже слитые зависимости. Полные configured checks выполняются на собранной фиче и на кандидате итогового squash в основную ветку. Ревью ребёнка использует focused доказательства разработки; полная матрица не повторяется на каждом ребёнке. Отдельный финальный developer зарезервирован для замечаний общего ревью и пропускается при обычном проходе. Done выставляет только пользователь.

Первая версия выполняет детей последовательно по DAG. Общая инфраструктура параллельных независимых запусков сохранена, но параллельная разработка детей этой фичи здесь не реализована. Это не внешние MR: ветки, результаты ревью и SHA отображаются в трекере, push не выполняется. Рабочие и интеграционные ветки сохраняются для разбора. Отмена останавливает последующие этапы; уже авторизованная короткая Git-транзакция может закончить публикацию в частную ветку, что не публикует фичу в основную. Изменение описания/плана родителя после разбиения останавливает использование старых дочерних планов.

Контекст детей: собственные исполняемые шаги; родительские требования и контракты хранятся как справочный контекст, а не дополнительные шаги разработки. Финальным ролям передаются ссылки и SHA доставок. В ключах checkpoint служебные даты и счётчики родственных карточек исключены; изменения требований и связей остаются значимыми.

Проверка: deterministic временный Git fixture проходит вопросы → ответ → остановка из-за бюджета → явное увеличение → восстановление аналитика без повторного вызова → два отдельных worktree → замечание ревью Beta → исправление → squash детей → общие тесты/review → один squash основной ветки. Инъекция сбоя подтверждения после доставки Alpha проверяет отсутствие повторного ревью/двойного слияния. DAG проверяется на циклы, дубликаты, отсутствующие планы и неизвестные зависимости. Headless очередь проверяет изменение бюджета без обнуления usage, дочерние ссылки и статусы. Платные модели и пользовательские задачи не запускались.
