# SAT-37: разработчик + тестировщик и доверенный запуск

## Результат

Основная новая команда состоит из разработчика и тестировщика. Разработчик начинает без внешнего аналитика и готового плана: сохраняет короткий implementationPlan через checkpoint в карточку, затем в той же беседе реализует задачу и focused unit tests. Тестировщик проверяет текущие исходники, diff и фактическое поведение; обнаруженные дефекты возвращаются разработчику. Настроенные проверки, подготовка worktree, отчёт и Git остаются обязанностью worker. Дополнительные роли и пользовательские команды сохранены.

Между моделями передаются требования, текущий план, пути файлов и короткие результаты. Полный diff и журнал исследования в следующий prompt не добавляются. Собственный сохранённый план не сбрасывает conversation; изменение внешних требований/плана меняет ключ продолжения. Checkpoint нужен для существенных результатов, перед долгой проверкой и остановкой, а не для счётчика инструментов.

В карточке PrimeNG checkbox «Доверенный запуск — без лимитов», по умолчанию выключен. Значение копируется при создании запуска: изменение карточки не меняет активную попытку. Агенты через MCP не могут включить его себе. Отключаются квоты worker по времени, токенам, вызовам, инструментам, revisions и resolver/merge attempts. Расход продолжает учитываться. Денежного потолка нет. Сохраняются ручная остановка, lease, права проекта, ограничения ресурсов, валидация, обязательные проверки и пользовательский done. В очереди и на карточке есть индикация.

Для Model API/Ollama добавлены save_progress, inspect_changes и вызов разрешённых MCP проекта. Managed MCP проекта поддерживается Codex и Model API/Ollama; для остальных CLI с указанным manifest MCP подготовка явно сообщает о неподдерживаемом адаптере. Доверенный запуск не расширяет список инструментов или права.

## Проверки

- Полный `npm test`: 162 теста пройдены до дополнительной регрессии миграций. Финальный полный suite через тот же tsx/reporter с `--test-concurrency=4`: 163 теста пройдены. При совместной нагрузке сборки и полного suite возникал timeout Git fixture; заключительный прогон ограничивает конкуренцию тестов.
- `npm run typecheck`: пройден.
- Синтетическая worker-регрессия: разработчик сохраняет план до правки; после контролируемого сбоя продолжает тот же conversation; тестировщик получает актуальные данные без тела исходников/полного diff; запуск доходит до review.
- Доверенный/обычный режим: false по умолчанию, запрет agent escalation, immutable snapshot, сохранение ручного cancel, обход tool/turn/time/token/call/revision квот в trusted. Все model responses имитированы, платные модели не вызывались.
- Реальный временный stdio MCP fixture: whitelist инструментов, ограниченный текст, явное указание пропущенных изображений, закрытие клиента.
- Headless UI на синтетическом хранилище: create/edit/default/persistence, planless enqueue dev/tester, очередь без лимитов, immutable snapshot, узкие экраны и отсутствие browser errors.

## Практические границы

Это уменьшает число платных ролей и передаваемый контекст; точная экономия зависит от модели и самой задачи. Реальную SAT-352 и другие платные задачи в рамках проверки не запускали. Самодекомпозиция, чтение актуального кода и тестирование всё ещё требуют токенов. Trusted означает отсутствие автоматической квоты worker, а не отсутствие провайдерских/системных ограничений.

Посторонние незавершённые UI-правки пользователя исключаются из коммита и production build; исходная рабочая копия сохраняется.

## Развёртывание

Чистый image server+web проверен headless UI перед развёртыванием. API/MCP и оба managed worker обновлены. Через MCP canonical pipelines Game1 (`default`) и `simple-ai-tracker` переключены на существующие developer/tester с сохранением всех профилей, моделей и подключений; пустая команда `assistent` не менялась. Existing run snapshots не менялись, доверенный режим ни одной пользовательской задаче автоматически не включался.

При первом рестарте обнаружена гонка API/MCP миграции: устаревший список pending после ожидания write lock мог повторно выполнить ALTER. MigrationRunner теперь повторно проверяет version внутри BEGIN IMMEDIATE; busy_timeout устанавливается до WAL. Синтетическая регрессия воспроизводит конкурирующее применение схемы и подтверждает отсутствие повторного ALTER. Данные production не читались и не правились напрямую.

При исчерпании бюджета через heartbeat теперь сохраняется исходная причина вместо ошибочной общей диагностики «потеря связи». Сфокусированная регрессия budget-worker и финальный suite зелёные.

Финальная проверка: HTTP 200; свежий MCP, карточка SAT-37 valid=true, encoding=ok, warnings/errors пусты, trustedExecution=false. Оба managed executor online/running. Посторонние четыре UI-файла сравнены с исходными копиями за вычетом собственных текстовых изменений SAT-37: сохранность подтверждена. Платные модели и пользовательские задачи не запускались.
